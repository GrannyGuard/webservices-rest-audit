# Mitigatie & validatie verbeteringen

Rubric: *"Verbeteronderzoek security"* — **Mitigatie & validatie verbeteringen** (20 pt).

Dit document beschrijft per kwetsbaarheid de genomen **mitigatie**, hoe die is
**gerealiseerd** (incl. (AI-)tooling, §6) en hoe **gevalideerd** is dat het risico is
verlaagd (voor/na). De validatie steunt op drie reproduceerbare bronnen:

1. **CodeQL-herscan** (SAST) — een alert gaat van `open` → `fixed`;
2. **Unit tests** (JUnit) — bewijzen het gedrag van de fix;
3. **Build** (`mvn -B clean install`) — bevestigt dat de wijziging compileert en geen
   regressie in de bestaande tests veroorzaakt.

> Pentest-**hervalidatie** van de meest kritische bevindingen (de "na"-meting met
> dezelfde aanvalsstappen) hoort in [`05-penetration-tests`](../05-penetration-tests/)
> en wordt in de testomgeving uitgevoerd; zie ook de restpunten onderaan.

## 2. SQ8 / CWE-79 — Reflected XSS in Swagger debug-endpoint

**Bevinding:** [04-code-review §2.2](../04-code-review/04.md#22-bevinding-2--reflected-xss-in-swagger-debug-endpoint-cwe-79-)
(CodeQL `java/xss`, alert **#1**, severity high). `SwaggerDocController.debug()`
reflecteert de query-parameter `tag` ongesanitized in een HTML-respons
(`return "<h1>Debugging Tag: " + tag + "</h1>";`).

**Besluit: geen code-fix — bewust niet gemitigeerd.**

De bevinding is vastgesteld via statische analyse en is inhoudelijk correct.
In de pentest-omgeving retourneert het endpoint echter HTTP 404 omdat Swagger
is uitgeschakeld via de global property `webservices.rest.enableSwaggerDocs`
(hardening-checklist §1). Daardoor is **functionele validatie van een code-fix
niet mogelijk**: elke pentest-hertest bevestigt slechts de 404, niet de werking
van output-encoding.

**Toegepaste maatregel (configuratie-niveau):**
- De gehele `/apiDocs`-boom is uitschakelbaar via `webservices.rest.enableSwaggerDocs`
  (zie [hardening-checklist §1](../01-security-audit/threat-model/hardening-checklist.md#1-onnodige-features-uitschakelen)).
  In productie op `false` retourneert het endpoint HTTP 404 — de aanvalsvector
  bestaat dan niet.
- Dit is de gekozen mitigatie: **least-functionality** (het endpoint is niet nodig
  in productie) i.p.v. output-encoding.

**Resterend risico:** als `webservices.rest.enableSwaggerDocs` ooit op `true` wordt
gezet zonder aanvullende maatregel, is de XSS bereikbaar. De aanbevolen definitieve
fix (`HtmlUtils.htmlEscape` op de `tag`-parameter) blijft als technische schuld
genoteerd voor dat scenario.

**Status:** ❌ **Open — bewust niet gemitigeerd** (code-fix niet valideerbaar via pentest;
productie-blootstelling afgedekt door configuratie-gating).

## 3. `AuthorizationFilter` — session-timeout fall-through (CWE-302, opgelost) + alert #908 (geaccepteerd risico)

### 3a. Session-timeout fall-through (CWE-302) — opgelost

**Bevinding:** [04-code-review §2.3](../04-code-review/04.md#23-bevinding-3--user-controlled-authentication-bypass-in-authorizationfilter-cwe-302-)
(handmatige review). Na een verlopen sessie werd
`sendError(401)` aangeroepen **zonder `return`**, waardoor de uitvoering doorliep naar
`chain.doFilter()` — de 401 werd verstuurd maar de request werd alsnog doorgegeven.
Dit is een fall-through (CWE-302-patroon), **niet** het CodeQL-alert #908 (zie §3b).

**Mitigatie:** `return;` toegevoegd direct na de `SESSION_TIMEOUT`-`sendError`
(`AuthorizationFilter.java`), zodat een timed-out request de keten daadwerkelijk stopt.

- **Realisatie/tooling:** Claude Code (Opus 4.8); één-regel-fix conform de aanbeveling
  in 04-code-review, handmatig gereviewd op neveneffecten (de "best-effort"-flow voor
  *credentials* blijft ongewijzigd — alleen de expliciete timeout-tak stopt nu).

**Validatie (voor/na):**

| | Vóór | Na |
|---|---|---|
| Verlopen sessie | 401 gezet, request loopt door naar `chain.doFilter()` | 401 gezet, keten gestopt (`return`) |
| `AuthorizationFilterLoggingTest` (12 tests) | groen | **groen** (geen regressie) |
| `chain.doFilter()` na een 401-op-timeout | bereikbaar (fall-through) | onbereikbaar (`return`) |

### 3b. CodeQL `java/user-controlled-bypass` #908 — geaccepteerd risico (false positive)

**Bevinding (geverifieerd 2026-06-15):** alert **#908** wijst naar
[`AuthorizationFilter.java:119`](../../omod-common/src/main/java/org/openmrs/module/webservices/rest/web/filter/AuthorizationFilter.java#L119)
— de aanroep `Context.authenticate(userAndPass[0], userAndPass[1])`. CodeQL-meldtekst:
*"sensitive method may not be executed depending on a condition which flows from
user-controlled value."* De aanroep is control-dependent op `if (basicAuth != null)` →
`if (basicAuth.startsWith("Basic"))`, beide afgeleid van de user-controlled
`Authorization`-header.

> ⚠️ **Correctie t.o.v. eerdere versies van dit document:** #908 is **niet** de
> session-timeout fall-through uit §3a, maar deze optionele-Basic-Auth-tak. De
> `return`-fix uit §3a sluit dit alert daarom niet — #908 stond na meerdere
> CodeQL-herscans op `main` (met `e3f3c7d` aanwezig) nog steeds `open`.

**Analyse — niet exploiteerbaar (faalt gesloten):** het overslaan van `Context.authenticate`
verleent géén toegang; de request blijft *unauthenticated* en OpenMRS handhaaft autorisatie
downstream (gooit een exception zodra een niet-geauthenticeerde caller een beschermde
resource benadert). De filter is *bewust* best-effort — Javadoc: *"It will not fail on
invalid or missing credentials. We count on the API to throw exceptions…"*. De conditionele
tak **verlaagt** dus het privilege i.p.v. het te verlenen. Het blok is bovendien **upstream
OpenMRS-code** (eerste import `eb72694`), niet door dit team geïntroduceerd.

**Waarom geen code-fix:** de control-dependency (alleen authenticeren *als* er een
Basic-header is) is inherent aan optionele Basic-Auth; een guard-clause of helper-extractie
verwijdert die dependency niet. De enige wijziging die het alert wél zou sluiten —
authenticatie *verplicht* maken — breekt het gedocumenteerde contract en de hele
REST-module (sessie/cookie-auth, publieke endpoints) en is dus een regressie, geen fix.
Dit is geen injectie-query, dus er is geen sanitizer/barrier (zoals bij CWE-117) toe te voegen.

**Besluit:** geaccepteerd risico, conform de afgesproken omgang met false positives
(Sprint 2, CI-scanning). #908 wordt in CodeQL gedismissed met onderbouwing
(reason: *won't fix* / accepted risk) en verwijzing naar deze sectie. Uit te voeren door
een repo-beheerder:

```bash
gh api -X PATCH repos/GrannyGuard/webservices-rest-audit/code-scanning/alerts/908 \
  -f state=dismissed -f dismissed_reason="won't fix" \
  -f dismissed_comment="Accepted risk (not exploitable) — best-effort optional Basic-Auth, fails closed, enforced downstream. See docs/security/06-mitigatie-en-validatie/06.md section 3b."
```

**Bewijsartefact:** na dismissal toont `gh api .../code-scanning/alerts/908`
`"state": "dismissed"` + `"dismissed_reason": "won't fix"` met de onderbouwing als comment.

## 4. SQ9 — Host-header injectie in de Swagger-specificatie

**Bevinding:** [01-security-audit §3.7 (TM-S4 / SQ9)](../01-security-audit/01.md#37-threat-model--c4-architectuur--stride-analyse).
`SwaggerSpecificationController` nam de client-`Host`- en `X-Forwarded-Proto`-headers
ongevalideerd over in de gepubliceerde OpenAPI-spec.

**Mitigatie:**
- `RestUtil.resolveSwaggerHost(host)` valideert de `Host` tegen de allow-list
  `webservices.rest.swaggerAllowedHosts`; een niet-toegestane host valt terug op de
  canonieke (eerste) host i.p.v. de client-waarde.
- `RestUtil.sanitizeScheme(scheme, default)` staat alleen `http`/`https` toe (blokkeert
  `X-Forwarded-Proto`-injectie).
- Bedraad in `SwaggerSpecificationController`; global properties in `config.xml`. Zie
  [hardening-checklist §10](../01-security-audit/threat-model/hardening-checklist.md#10-openapi-specificatie-alleen-naar-specifieke-allowed-hosts).
- **Realisatie/tooling:** Claude Code (Opus 4.8); logica bewust in testbare helpers in
  `RestUtil` gezet i.p.v. inline in de controller.

**Validatie (voor/na):** unit tests `SwaggerHardeningRestUtilTest` — **8/8 groen**:

| Test | Bewijst |
|---|---|

## 6. F-01 — Geen rate limiting (CWE-307)

**Bevinding:** [PentestReport §6 — F-01](../05-penetration-tests/PentestReport-OpenMRS.md#6-f-01--geen-rate-limiting-cwe-307) — NEN-7510 A.8.5 (toegangsbeveiliging), A.8.15 (logging beveiligingsgebeurtenissen).

**Mitigatie:**
- **Aanpak:** in-memory IP-rate-limiter in `AuthorizationFilter`: bounded `ConcurrentHashMap<String, long[]>` (max 10.000 entries als safety valve) bijhoudt `{ failedAttemptCount, windowStartEpochMs }` per bron-IP. Max 10 mislukte pogingen per 60-secondenvenster → HTTP 429 + `return` vóór `Context.authenticate()` aangeroepen wordt; teller reset bij succesvolle authenticatie via `clearFailedAttempts`. Log op WARN: `ACCESS_BLOCKED rate_limited=true ip=[...] uri=[...]` (NEN-7510 A.8.15).
- **Gewijzigd bestand:** [`omod-common/.../web/filter/AuthorizationFilter.java`](../../omod-common/src/main/java/org/openmrs/module/webservices/rest/web/filter/AuthorizationFilter.java) — nieuwe methoden `isRateLimited`, `recordFailedAttempt`, `clearFailedAttempts`, `resetRateLimitState` + uitbreiding `doFilter` (commit `59bf421`).
- **Realisatie/tooling:** Claude Code (Sonnet 4.6); `ConcurrentHashMap` i.p.v. Guava Cache gekozen voor Java 8-compatibiliteit zonder extra dependency; benign read-race buiten `compute` bewust geaccepteerd (voldoende precisie voor rate limiting).

**Validatie (voor/na):**

| | Vóór fix | Ná fix |
|---|---|---|
| 11e achtereenvolgende mislukte Basic Auth-poging (Kali — 2026-06-16) | HTTP 200 (nooit geblokkeerd) | **HTTP 429** |
| Docker-log op 11e poging | geen blokkade-entry | `WARN ACCESS_BLOCKED rate_limited=true ip=[172.22.0.1]` |

## 8. F-04 — Stack Trace Disclosure (CWE-209)

**Bevinding:** [PentestReport §9 — F-04](../05-penetration-tests/PentestReport-OpenMRS.md#9-f-04--stack-trace-disclosure-cwe-209) — NEN-7510 A.8.15 (logging beveiligingsgebeurtenissen), A.8.5 (toegangsbeveiliging).

**Mitigatie:**
- **Aanpak A (`RestUtil`):** In `RestUtil.wrapErrorResponse()` werd het `code`-veld gevuld met `className:lineNumber` (bv. `org.openmrs.api.context.Context:753`) en het `detail`-veld met de volledige stack trace. - **Realisatie/tooling:** Claude Code (Sonnet 4.6); deployment-probleem gediagnosticeerd (data-volume vs. bind-mount) en opgelost door directe kopie van de nieuwe `.omod` naar `/openmrs/data/modules/` in de container; 4 tests bijgewerkt/toegevoegd.

## 9. F-06 — Integer Overflow in Paginering (CWE-190)

**Bevinding:** [PentestReport §11 — F-06](../05-penetration-tests/PentestReport-OpenMRS.md#11-f-06--integer-overflow-in-paginering-cwe-190) — NEN-7510 A.8.28 (veilige softwareontwikkeling).

**Mitigatie:**
- **Aanpak:** `RestUtil.getIntegerParam()` gebruikte `new Integer(paramString)`, dat intern `Integer.parseInt()` aanroept. Voor `2147483648` (> `Integer.MAX_VALUE`) gooit dat een `NumberFormatException` — die werd gevangen en als `null` teruggegeven, waarna de aanvraag met de standaardlimiet (50) HTTP 200 retourneerde. Fix: `Long.parseLong()` als eerste stap, gevolgd door een expliciete bereikcontrole (`< Integer.MIN_VALUE || > Integer.MAX_VALUE`). Out-of-range waarden gooien nu een `IllegalArgumentException` die doorpropageert naar `BaseRestController.handleException()` → HTTP 500 (generiek bericht + UUID, geen stack trace).
- **Gewijzigd bestand:** [`omod-common/.../web/RestUtil.java`](../../omod-common/src/main/java/org/openmrs/module/webservices/rest/web/RestUtil.java) — `getIntegerParam()` methode: `new Integer(paramString)` vervangen door `Long.parseLong()` + bereikcontrole.
- **Realisatie/tooling:** Claude Code (Sonnet 4.6); minimale één-methode-fix die zowel `limit` als `startIndex` afdekt (beide doorlopen dezelfde `getIntegerParam`-methode); 3 nieuwe tests in `RestUtilTest`.

**Validatie (voor/na):**

| | Vóór fix | Ná fix |
|---|---|---|
| `?limit=2147483648` — HTTP-statuscode | **200** (overflow, standaardlimiet gebruikt) | **500** |
| `?limit=2147483648` — response body | volledige resultatenlijst (50 items) | `{"error": {"message": "An internal server error occurred", "code": "<uuid>", "detail": ""}}` |
| `?limit=100` (grenswaarde) | 200 of 500 | **403** (geaccepteerd; testuser mist `/concept`-privilege — correct gedrag) |
| `?limit=101` (boven absolute limiet) | 500 | **500** (ongewijzigd) |
| `RestUtilTest` (3 nieuwe tests) | niet aanwezig | **3/3 groen** |

`mvn clean install` (omod-common) groen — 23 tests, 0 fouten.

## 10. F-09 — Cookie Zonder SameSite Attribute (CWE-1275)

**Bevinding:** [PentestReport §14 — F-09](../05-penetration-tests/PentestReport-OpenMRS.md#14-f-09--cookie-zonder-samesite-attribute-cwe-1275) — NEN-7510 A.8.23 (webfiltering).

**Mitigatie (twee lagen):**

De JSESSIONID wordt door Tomcat intern gezet via een eigen response-pipeline, buiten de
Servlet filter API om. Een applicatie-level filter alleen is daarvoor onvoldoende; twee
complementaire lagen zijn nodig:

- **Laag 1 — Servlet filter** (`SameSiteCookieFilter.java`): nieuwe
  `javax.servlet.Filter` in `omod-common` die de `HttpServletResponse` omhult met
  `SameSiteResponseWrapper extends HttpServletResponseWrapper`. Elke
  `addHeader`/`setHeader`-aanroep voor `Set-Cookie` en elke `addCookie()`-aanroep wordt
  onderschept; `SameSite=Strict` en `Secure` worden toegevoegd als ze ontbreken.
  Geregistreerd in `config.xml` als eerste filter op `/ws/rest/*`. Dekt applicatie-level
  cookies gezet via de Servlet API.

- **Laag 2 — Tomcat `CookieProcessor`** (`docker/tomcat/context.xml`): Tomcat 9.x
  biedt de `sameSiteCookies`-attribuut op de `Rfc6265CookieProcessor`. Waarde `"strict"`
  zorgt dat Tomcat zelf `; SameSite=Strict` toevoegt aan alle cookies inclusief JSESSIONID.
  Bestand volume-gemount in `docker-compose.yml`
  (`./docker/tomcat/context.xml:/usr/local/tomcat/conf/context.xml:ro`).

- **Gewijzigde bestanden:**
  - [`omod-common/.../filter/SameSiteCookieFilter.java`](../../omod-common/src/main/java/org/openmrs/module/webservices/rest/web/filter/SameSiteCookieFilter.java) — nieuw
  - [`omod/src/main/resources/config.xml`](../../omod/src/main/resources/config.xml) — filterregistratie
  - [`docker/tomcat/context.xml`](../../docker/tomcat/context.xml) — nieuw
  - [`docker-compose.yml`](../../docker-compose.yml) — volume-mount toegevoegd

- **Realisatie/tooling:** Claude Code (Sonnet 4.6); `HttpServletResponseWrapper`-aanpak
  gekozen omdat de `Cookie` API in Servlet 3.1 geen native SameSite-ondersteuning heeft.
  Testopzet gebruikt een eigen `HeaderCapture`-wrapper i.p.v. `MockHttpServletResponse`,
  omdat die intern `Cookie.isHttpOnly()` aanroept — een methode die niet bestaat in de
  Servlet 2.5 API jar van dit project (`NoSuchMethodError` bij directe mock-aanroep).

**Validatie (voor/na):**

| | Vóór fix | Ná fix |
|---|---|---|
| `Set-Cookie` op geauthenticeerde sessie | `JSESSIONID=...; Path=/openmrs; HttpOnly` | `JSESSIONID=...; Path=/openmrs; HttpOnly; SameSite=Strict` |
| `Set-Cookie` op ongeauthenticeerde call | idem, geen SameSite | `SameSite=Strict` aanwezig |
| `grep -i samesite` op response | geen output | output niet leeg |
| `SameSiteCookieFilterTest` (10 tests) | niet aanwezig | **10/10 groen** |

`mvn clean install` (omod-common) groen — 10 tests voor `SameSiteCookieFilter`, 0 fouten.

## 11. F-08 — Ontbrekende Security Headers (CWE-693)

**Bevinding:** [PentestReport §13 — F-08](../05-penetration-tests/PentestReport-OpenMRS.md#13-f-08--ontbrekende-security-headers-cwe-693) — NEN-7510 A.8.23 (webfiltering).

**Mitigatie:**
- **Aanpak:** Nieuwe `SecurityHeadersFilter` in `omod-common` die zes HTTP-security-headers op elke response zet via `HttpServletResponse.setHeader()`. De filter roept daarna `chain.doFilter()` aan zodat de request-verwerking normaal doorgaat. Geregistreerd in `config.xml` als eerste filter op `/ws/rest/*` vóór SameSite en Authorization.

  - [`omod/src/main/resources/config.xml`](../../omod/src/main/resources/config.xml) — filterregistratie
- **Realisatie/tooling:** Claude Code (Sonnet 4.6); minimale filter zonder configuratie-overhead, patroon identiek aan `ContentTypeFilter` en `SameSiteCookieFilter` in dezelfde module. `CSP: default-src 'none'` gekozen omdat de REST module uitsluitend JSON serveert — restrictieve policy zonder whitelisting nodig.

## 13. Kritische reflectie

- **Sterk:** de code-fixes zijn klein, bibliotheek-gebaseerd en testbaar gemaakt
  (helpers in `RestUtil` i.p.v. inline, rate limiter als afzonderlijke methoden in
  `AuthorizationFilter`), wat reproduceerbare unit-validatie mogelijk maakt en de
  kans op regressie minimaliseert (bevestigd: 127 tests, 0 fouten na elke fix).
- **Validatiediepte — inmiddels afgesloten voor de kritische bevindingen:** unit tests
  bewijzen de *logica*, niet de volledige HTTP-keten. Voor SQ8 is de **CodeQL-herscan**
  de definitieve "na"-meting (§2); #908 is een **onderbouwde dismissal** (§3b). Voor
  F-07 (log injection) en F-01 (rate limiting) is de cirkel inmiddels kwantitatief
  gesloten via **pentest-hertest op Kali** (2026-06-16): F-07 toont sanitisatie in
  `AuthorizationFilter` met restrisico in OpenMRS Core (out-of-scope, gedocumenteerd);
  F-01 bevestigt HTTP 429 op de 11e poging; F-02 bevestigt privilege-blokkade en uniforme logs; F-04 bevestigt leeg `detail`-veld en HTTP 403 i.p.v. 500; F-06 bevestigt HTTP 500 i.p.v. 200 voor overflow-waarden. Zie restpunten voor nog openstaande hertests (F-09 e.v.).
- **Beperking — gating defaultt op `true`:** `enableSwaggerDocs` staat standaard aan om
  bestaand gedrag niet te breken; de productie-winst hangt dus af van een correcte
  OTAP-configuratie (`false`). Bewuste afweging (compatibiliteit vs. secure-by-default),
  als zodanig gedocumenteerd.
- **Beperking — least-privilege DB:** het mechanisme is aanwezig, maar de runtime-switch
  naar het DML-only account is een deploy-stap die in deze omgeving niet
  container-geverifieerd kon worden (Docker-daemon niet beschikbaar).
- **Tooling:** AI (Claude Code Opus 4.8 / Sonnet 4.6) versnelde lokaliseren + boilerplate
  (tests, helpers), maar de beveiligingsbeslissingen (welke fix, welke afweging) zijn
  menselijk genomen en geverifieerd; CodeQL/unit tests/pentest — niet de AI — zijn het bewijs.
