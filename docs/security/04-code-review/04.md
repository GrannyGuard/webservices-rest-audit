# Security code review & kwetsbaarheden

Rubric: *"Verbeteronderzoek security"* — **Security code review & kwetsbaarheden** (15 pt).
NEN-7510 controls: **A.8.25** (veilige ontwikkelcyclus), **A.8.28** (veilig coderen), **A.8.29** (beveiligingstests).

---

## 1. Methodologie

De code review is gelaagd opgezet: geautomatiseerde tooling vormt de eerste verdedigingslinie en menselijke beoordeling vormt de laatste poort vóór merge. De bevindingsnummering (**F-01 t/m F-09**) is bewust gelijkgesteld aan het penetratietestrapport ([05-penetration-tests](../05-penetration-tests/PentestReport-OpenMRS.md)) zodat beide documenten één op één traceerbaar zijn. Aanvullende bevindingen die uitsluitend via statische analyse zijn gevonden (geen pentest-equivalent) staan in §2.10.

### Geautomatiseerde tooling

**SonarCloud (SAST)**
Elke pull request triggert een SonarCloud-analyse. De pipeline is geconfigureerd als *quality gate*: een pull request waarop de quality gate faalt (bv. een nieuw security hotspot of een reliability-issue met rating slechter dan A) kan niet gemerged worden totdat het probleem handmatig is opgelost of expliciet gedocumenteerd afgewogen.

**CodeQL (SAST, query-suite `security-extended`)**
GitHub Advanced Security voert bij elke push een CodeQL-scan uit met de `security-extended` query-suite (zie [ADR-001](../02-secure-pipelines/adr-001-codeql-query-suite-scope.md) voor de keuzeonderbouwing). Alerts verschijnen als *code scanning alerts* in de GitHub Security-tab. De organisatie-instelling blokkeert merge bij nieuwe hoog-risico-alerts totdat deze worden opgelost of als `false positive` gedismisst met onderbouwing.

**SBOM & CVE-check (SCA)**
Bij elke pull request wordt een CycloneDX SBOM gegenereerd en gecontroleerd op bekende CVE's (via Dependency-Review Action / Snyk). Een pull request met afhankelijkheden die een CVE bevatten boven de drempelwaarde faalt automatisch.

**GitHub Advanced Security — AI-ondersteunde review (Copilot Autofix)**
GitHub's ingebouwde AI-tooling (Copilot Autofix) analyseert CodeQL-alerts en genereert suggesties voor mitigatie rechtstreeks als PR-commentaar. Deze suggesties zijn niet blindelings overgenomen: elke autofix-suggestie is handmatig beoordeeld op correctheid en contextrelevantie voordat deze werd toegepast of verworpen.

### Verplichte menselijke review

Op organisatieniveau is *required reviewers* afgedwongen: elke pull request vereist minimaal één goedkeuring van een ander teamlid voordat merge is toegestaan. De combinatie van automatische gate (SonarCloud, CodeQL, SBOM) én menselijke goedkeuring zorgt dat kwetsbaarheden die door tooling worden gevlagd altijd een expliciete beslissing vereisen.

### Handmatig onderzochte bestanden

Op basis van het aanvalsoppervlak-overzicht (Sprint 3) en de pentest-bevindingen zijn de volgende bestanden en endpoints handmatig gereviewed:

- `AuthorizationFilter.java` — toegangscontrole, authenticatieverwerking, rate-limiting, sessie-validatie
- `SessionController1_9.java` — sessiebeheer, inlogstroom, `/session/diag`-endpoint
- `BaseDelegatingResource.java` — centrale resource-routing met brede rechtenimpact
- `SystemInformationResource1_8.java` — versie- en configuratiebeheer endpoint
- `RequestContext.java` — invoervalidatie paginatieparameters
- `web.xml` (Tomcat) — HTTP-niveau configuratie: headers, cookie-attributen

## 2. Bevindingen

Per bevinding zijn drie perspectieven gecombineerd: **(1)** de code-locatie die de kwetsbaarheid veroorzaakt of mogelijk maakt, **(2)** de pentest-bevestiging (of afwezigheid daarvan), en **(3)** een eigen reële-impact-inschatting gekoppeld aan het zorgdomein. Dit laatste is vereist voor het rubric-onderdeel *"duidelijke relatie kwetsbaarheid↔systeemgebruik"*.

### 2.1 F-01 — Ontbrekende rate limiting op authenticatie-endpoint (CWE-307) 🔴

| | |
|---|---|
| **Ernst** | 🔴 Kritiek |
| **CWE** | CWE-307 — Improper Restriction of Excessive Authentication Attempts |
| **OWASP 2021** | A07 — Identification and Authentication Failures |
| **NEN-7510** | A.8.5 — Veilige authenticatie |
| **Bron** | Handmatige review `AuthorizationFilter.java` |

**Code-locatie:**
`omod-common/.../web/filter/AuthorizationFilter.java:113`

```java
Context.authenticate(userAndPass[0], userAndPass[1]);
```

Het klassecommentaar stelt expliciet dat de filter *"will not fail on invalid or missing credentials"* en *"never stops execution"*. Er is geen teller, geen vertraging en geen blokkade na herhaalde mislukte pogingen op HTTP-niveau. De bestaande OpenMRS account-lockout (op applicatieniveau, na ~7 pogingen) geldt **niet** voor niet-bestaande gebruikersnamen — een aanvaller kan een wachtwoordlijst doorlopen totdat een account wordt gevonden dat de lockout-drempel niet bereikt.

**Pentest-bevestiging (F-01):** 50 opeenvolgende pogingen op een niet-bestaand account → geen HTTP 429, geen vertraging. Admin-credentials (`admin:Admin123!`) verkregen in poging 6 van 84, binnen 2 seconden. Zie [PentestReport §6](../05-penetration-tests/PentestReport-OpenMRS.md#6-f-01--geen-rate-limiting-cwe-307).

**Reële impact:** In een ziekenhuisomgeving zijn zwakke wachtwoorden (naam + geboortejaar, afdelingsnaam) realistisch. Een gecompromitteerd klinisch account geeft volledige toegang tot patiëntdossiers (KJ1, KJ2 — AVG Art. 9, WGBO Art. 7:454). De aanval duurt minder dan 2 seconden — beduidend sneller dan enige menselijke detectie.

**Aanbeveling:** Rate limiting op HTTP-niveau (max. 10 pogingen/min per IP → HTTP 429), exponentieel backoff, IP-niveau lockout naast per-account lockout.

**Status:** ✅ **Gemitigeerd** — in-memory IP-rate-limiter in `AuthorizationFilter` (commit `59bf421`); HTTP 429 na 10 pogingen, Kali-hervalidatie 2026-06-16. Zie [06-mitigatie §6](../06-mitigatie-en-validatie/06.md#6-f-01--geen-rate-limiting-cwe-307).

### 2.2 F-02 — Gebruikersenumeratie via `/user` API (CWE-204) 🟠

| | |
|---|---|
| **Ernst** | 🟠 Hoog |
| **CWE** | CWE-204 — Observable Response Discrepancy |
| **OWASP 2021** | A07 — Identification and Authentication Failures |
| **NEN-7510** | A.8.5 — Veilige authenticatie |
| **Bron** | Handmatige review `/user`-endpoint |

**Code-locatie:**
`omod/.../v1_0/resource/.../UserResource*.java` — de `/ws/rest/v1/user`-endpoint retourneert een volledige lijst van alle gebruikersaccounts zonder additionele rolbeperking boven basisauthenticatie. Elke geauthenticeerde aanvaller (ook met een laag-geprivilegieerd account) kan alle gebruikersnamen en details ophalen:

```json
GET /ws/rest/v1/user
Authorization: Basic <laag-geprivilegieerde-creds>

{
  "results": [
    { "display": "admin", "username": "admin", ... },
    { "display": "doctor", "username": "doctor", ... },
    ...
  ]
}
```

**Pentest-bevestiging (F-02):** `GET /ws/rest/v1/user` met geldige credentials retourneerde de volledige gebruikerslijst inclusief `admin`. Zie [PentestReport §7](../05-penetration-tests/PentestReport-OpenMRS.md#7-f-02--gebruikersenumeratie-cwe-204).

**Reële impact:** Aanvaller verkrijgt een volledige lijst van geldige gebruikersnamen zonder extra validatie. Maakt gerichte brute-force (F-01) significant efficiënter — specifiek gericht op bestaande accounts vermindert de zoekruimte drastisch. In een ziekenhuisomgeving zijn gebruikersnamen vaak voorspelbaar (voornaam, functie, afdeling). Een account met minimale privileges (bv. laboratorium-technici) kan alle systeem-administratoraccounts enumereren.

**Aanbeveling:** Beperk `/user` API tot een expliciete beheerdersrol; retourneer geen gevoelige accountdetails aan lager-geprivilegieerde gebruikers.

**Status:** ✅ **Gemitigeerd** — `requirePrivilege(GET_USERS)` op `/user` (Methode A) + uniforme `AUTH_FAILURE` log (Methode B); Kali-hervalidatie 2026-06-16. Zie [06-mitigatie §7](../06-mitigatie-en-validatie/06.md#7-f-02--gebruikersenumeratie-cwe-204).

### 2.3 F-03 — Session Fixation — sessie-ID niet geroteerd na authenticatie (CWE-384) 🟠

| | |
|---|---|
| **Ernst** | 🟠 Hoog |
| **CWE** | CWE-384 — Session Fixation |
| **OWASP 2021** | A07 — Identification and Authentication Failures |
| **NEN-7510** | A.8.5 — Veilige authenticatie, A.8.3 — Toegangsbeveiliging |
| **Bron** | Handmatige review `AuthorizationFilter.java` |

**Code-locatie:**
`omod-common/.../web/filter/AuthorizationFilter.java:113`

```java
Context.authenticate(userAndPass[0], userAndPass[1]);
// ← na succesvolle login: géén session.invalidate() aanroep
// ← het bestaande JSESSIONID blijft geldig
```

Na `Context.authenticate()` wordt het bestaande sessie-object **niet** geïnvalideerd en een nieuw sessie-ID aangemaakt. Spring Security biedt standaard session-fixation protection via `session-fixation protection="newSession"`, maar dit is in deze filter-gebaseerde implementatie niet geconfigureerd. Een aanvaller die vóór login het JSESSIONID van het slachtoffer kent (via netwerk-onderschepping — zie ook F-09, cookie zonder Secure flag) kan dit ID na login hergebruiken.

**Pentest-bevestiging (F-03):** JSESSIONID voor login (`108D432C8C85187F4CBE53C0214A586C`) == JSESSIONID na login — identiek. Zie [PentestReport §8](../05-penetration-tests/PentestReport-OpenMRS.md#8-f-03--session-fixation-cwe-384).

**Reële impact:** Sessie-overname zonder credentials. Een aanvaller met een geplant sessie-ID krijgt toegang tot patiëntdossiers (KJ1, KJ2) met de rechten van het slachtoffer — directe AVG Art. 33-meldplicht en risico op verkeerde zorgbeslissingen bij gemanipuleerde dossiers. In combinatie met F-09 (cookie zonder Secure flag) is onderschepping triviaal op netwerken zonder TLS.

**Aanbeveling:** `HttpSession.invalidate()` aanroepen na `Context.authenticate()`, gevolgd door een nieuwe sessie aanmaken. In Spring Security: `session-fixation protection="newSession"`.

**Status:** ✅ **Gemitigeerd** — `session.invalidate()` + `getSession(true)` na `Context.authenticate()` in `AuthorizationFilter`; Kali-hervalidatie 2026-06-17. Zie [06-mitigatie §13](../06-mitigatie-en-validatie/06.md#13-f-03--session-fixation-cwe-384).

### 2.4 F-04 — Stack Trace Disclosure — interne details in HTTP-responses (CWE-209) 🟠

| | |
|---|---|
| **Ernst** | 🟠 Hoog |
| **CWE** | CWE-209 — Generation of Error Message Containing Sensitive Information |
| **OWASP 2021** | A09 — Security Logging and Alerting Failures |
| **NEN-7510** | A.8.15 — Logging, A.8.28 — Veilig coderen |
| **Bron** | Handmatige review — afwezigheid van globale exception handler |

**Code-locatie (afwezigheid):**
Er is **geen** `@ControllerAdvice` / `@ExceptionHandler(Exception.class)` aanwezig die interne uitzonderingsdetails omzet naar een generiek foutbericht. De default Spring MVC-foutafhandeling propageert de volledige exception-message — inclusief klassenamen, regelnummers, Hibernate ORM-structuur en afhankelijkheidsversies — naar de HTTP-responsebody.

De volgende soorten informatie lekken via stack traces in de responses:
- `org.openmrs.aop.AuthorizationAdvice:120` → exacte autorisatielaag + regelnummer
- `org.hibernate.collection.internal.PersistentSet` → Hibernate-versie en ORM-configuratie
- `com.fasterxml.jackson.databind.JsonMappingException` → Jackson-afhankelijkheidsversie
- `org.openmrs.Role.getId(Role.java:246)` → intern domeinmodel

**Pentest-bevestiging (F-04):** `GET /ws/rest/v1/user` (unauthenticated), `GET /ws/rest/v1/module`, `POST /ws/rest/v1/user` → alle drie retourneren volledige Java stack traces (~80 regels per respons). Zie [PentestReport §9](../05-penetration-tests/PentestReport-OpenMRS.md#9-f-04--stack-trace-disclosure-cwe-209).

**Reële impact:** Stack traces maken vervolgaanvallen significant eenvoudiger: exacte framework-versies voor CVE-targeting (zie [03-sbom §4](../03-sbom-en-cve-advies/03.md)), ORM-configuratie voor deserialisatie-analyse, en autorisatiearchitectuur voor privilege escalation op patiëntdossiers (KJ1, KJ2).

**Aanbeveling:** Implementeer een globale `@ControllerAdvice` met `@ExceptionHandler(Exception.class)` die interne details vervangt door een generiek JSON-foutbericht met referentie-ID. Log de volledige trace intern (NEN-7510 A.8.15) maar stuur nooit details naar de client.

**Status:** ✅ **Gemitigeerd** — `RestUtil.wrapErrorResponse()` leegt `code`/`detail`; `BaseRestController` stuurt `ContextAuthenticationException` → HTTP 403; Kali-hervalidatie 2026-06-16. Zie [06-mitigatie §8](../06-mitigatie-en-validatie/06.md#8-f-04--stack-trace-disclosure-cwe-209).

### 2.5 F-05 — Versie- en configuratie-informatie via publieke endpoints (CWE-200) 🟠

| | |
|---|---|
| **Ernst** | 🟠 Hoog |
| **CWE** | CWE-200 — Exposure of Sensitive Information |
| **OWASP 2021** | A02 — Security Misconfiguration |
| **NEN-7510** | A.8.15 — Logging, A.8.3 — Toegangsbeveiliging |
| **Bron** | Handmatige review `SystemInformationResource1_8.java` + `SessionController1_9.java` |

**Code-locatie A — `/ws/rest/v1/systeminformation`:**
`omod/.../v1_0/resource/openmrs1_8/SystemInformationResource1_8.java:26`

```java
public SimpleObject getAll(RequestContext context) throws ResponseException {
    SimpleObject rest = new SimpleObject();
    rest.put("systemInfo", Context.getAdministrationService().getSystemInformation());
    return rest;
}
```

De resource implementeert `Listable` zonder expliciete privilege-check in de resource zelf. `getSystemInformation()` retourneert onder andere OpenMRS-versie, Java-versie, database-URL (`jdbc:mysql://db:3306/openmrs?...`) en database-gebruikersnaam — gevoelige configuratiedata die elke (basis-)geauthenticeerde aanvaller kan opvragen.

**Code-locatie B — `/ws/rest/v1/session/diag`:**
`omod/.../v1_0/controller/openmrs1_9/SessionController1_9.java:172–187`

```java
@RequestMapping(value = "/diag")
// NOTE: No authorization check — accessible to any caller (authenticated or not)
```

Bij een actieve sessie retourneert het endpoint de volledige rol- en privilege-set (`userRoles`, `userPrivileges`). Dit geeft een aanvaller een blauwdruk van de rechtenstructuur vóórdat een aanval op een hoog-geprivilegieerd account wordt uitgevoerd.

**Pentest-bevestiging (F-05):** `/systeminformation` retourneerde OpenMRS 2.8.7, Java 17.0.19, database-URL én gebruikersnaam. Zie [PentestReport §10](../05-penetration-tests/PentestReport-OpenMRS.md#10-f-05--versie-informatie-disclosure-cwe-200).

**Reële impact:** Exacte versies stellen een aanvaller in staat CVE's gericht te selecteren (vgl. de 264 open Dependabot-alerts in [03-sbom §3](../03-sbom-en-cve-advies/03.md)). Database-URL en gebruikersnaam zijn directe aanknopingspunten voor een aanval op de datalaag (KJ1 — patiëntidentiteit).

**Aanbeveling:** Beperk `/systeminformation` tot een specifieke beheerdersrol; verwijder database-URL en gebruikersnaam uit de output. Voeg een autorisatiecheck toe op `/session/diag` of verwijder het endpoint uit productiebuilds.

**Status:** ✅ **Gemitigeerd** (deels) — privilege check (`GET_GLOBAL_PROPERTIES`) + redactie `connectionURL`/`userName` in `SystemInformationResource1_8`; Kali-hervalidatie 2026-06-17. Restrisico: Tomcat-versie in `robots.txt`/`sitemap.xml` (buiten module-scope). Zie [06-mitigatie §12](../06-mitigatie-en-validatie/06.md#12-f-05--versie-informatie-disclosure-cwe-200).

### 2.6 F-06 — Integer overflow in paginatieparameters (CWE-190/191) 🟡

| | |
|---|---|
| **Ernst** | 🟡 Middel |
| **CWE** | CWE-190 — Integer Overflow / CWE-191 — Integer Underflow |
| **OWASP 2021** | A04 — Insecure Design |
| **NEN-7510** | A.8.28 — Veilig coderen (invoervalidatie) |
| **Bron** | CodeQL `java/tainted-arithmetic` (alerts **#5** en **#6**, severity **high**) |

**Code-locatie:**
`omod-common/.../web/RequestContext.java:172,183`

```java
query += … + (startIndex + limit);   // regel 172 — overflow mogelijk
int prevStart = startIndex - limit;  // regel 183 — underflow (maar daarna geklemd)
```

De paginatieparameters `startIndex` en `limit` worden als Java `int` (32-bit signed) verwerkt. Waarden groter dan `Integer.MAX_VALUE` (2.147.483.647) wrappen naar negatief: `(int) 2147483648L = -2147483648`. De `>0`-validatie en de absolute limiet van 100 resultaten worden daarmee omzeild.

**Pentest-bevestiging (F-06):** `limit=2147483648` → HTTP 200 zonder foutmelding; `startIndex=-1` geaccepteerd. Zie [PentestReport §11](../05-penetration-tests/PentestReport-OpenMRS.md#11-f-06--integer-overflow-in-paginering-cwe-190).

**Reële-impact-inschatting:** **Laag**. Het resultaat wordt enkel gebruikt om `next`/`prev`-hyperlinks te bouwen; een overflow levert hooguit een onjuiste `startIndex` in een paginatielink op. Java-integers wrappen veilig, er is geen geheugen- of databasecorruptie. Regel 183 is bovendien al geklemd. Wel correct om `limit`/`startIndex` server-side te begrenzen als DoS-beperking bij grote datasets.

**Aanbeveling:**
```java
long rawLimit = Long.parseLong(limitParam);
if (rawLimit < 1 || rawLimit > MAX_ALLOWED) throw new ValidationException("...");
int limit = (int) rawLimit;
```

**Status:** ✅ **Gemitigeerd** — `Long.parseLong()` + bereikcontrole in `RestUtil.getIntegerParam()`; `limit=2147483648` retourneert HTTP 500; Kali-hervalidatie 2026-06-16. Zie [06-mitigatie §9](../06-mitigatie-en-validatie/06.md#9-f-06--integer-overflow-in-paginering-cwe-190).

| **CWE** | CWE-117 — Improper Output Neutralization for Logs |
| **OWASP 2021** | A09 — Security Logging and Alerting Failures |
| **NEN-7510** | A.8.15 — Logging |
| **Bron** | CodeQL `java/log-injection` (9 alerts, scan `e476489`); handmatige review `AuthorizationFilter.java` |

**Code-locatie (vóór fix, commit `8521cdc`):**
- `omod-common/.../web/RestUtil.java:521`
- `omod/.../ClearDbCacheController2_0.java:79,86,95`
- `omod/.../SearchIndexController2_0.java:77,81`
- `omod/.../ConceptResource1_8.java:567`

De controllers logden request-afgeleide waarden direct in `log.warn()`/`log.info()` zonder CR/LF-neutralisatie, waardoor een aanvaller neppe logregels kon injecteren ("log forging").

### 2.8 F-08 — Ontbrekende HTTP security headers (CWE-693) 🔵

| | |
|---|---|
| **Ernst** | 🔵 Laag |
| **CWE** | CWE-693 — Protection Mechanism Failure |
| **OWASP 2021** | A02 — Security Misconfiguration |
| **NEN-7510** | A.8.23 — Webfiltering |
| **Bron** | Handmatige review Tomcat-configuratie / `web.xml` |

**Code-locatie (afwezigheid):**
Er is **geen** `HttpHeaderSecurityFilter` geconfigureerd in de Tomcat `web.xml` van het OpenMRS WAR-bestand. De volgende beschermende headers ontbreken op alle responses:

| Header | Ontbrekende bescherming |
|---|---|
| `Content-Security-Policy` | XSS-aanvallen mogelijk bij injectiepunt (vgl. F-02/SQ8) |
| `X-Frame-Options` | Clickjacking-aanvallen mogelijk |
| `X-Content-Type-Options` | MIME-type sniffing |
| `Strict-Transport-Security` | Downgrade naar onversleuteld HTTP mogelijk |

Tomcat 9 voegt deze headers niet standaard toe; ze moeten expliciet worden geconfigureerd via de `HttpHeaderSecurityFilter` of een reverse proxy.

**Pentest-bevestiging (F-08):** Nikto-scan bevestigde afwezigheid van alle vier headers op alle endpoints. ZAP-scan flagde dit als bevinding. Zie [PentestReport §13](../05-penetration-tests/PentestReport-OpenMRS.md#13-f-08--ontbrekende-security-headers-cwe-693).

**Reële impact:** Laag als stand-alone, maar versterkt andere risico's: zonder CSP is elke XSS-kwetsbaarheid (vgl. SQ8) exploitabeler; zonder HSTS is F-09 (cookie onderschepping) realistischer.

**Aanbeveling:** In Tomcat `web.xml` de `HttpHeaderSecurityFilter` inschakelen met `hstsEnabled`, `antiClickJackingEnabled` en `blockContentTypeSniffingEnabled`.

**Status:** ✅ **Gemitigeerd** — `SecurityHeadersFilter` zet 6 headers op elke `/ws/rest/*` response; Kali-hervalidatie 2026-06-17 bevestigt alle headers. Zie [06-mitigatie §11](../06-mitigatie-en-validatie/06.md#11-f-08--ontbrekende-security-headers-cwe-693).

### 2.9 F-09 — Session cookie zonder SameSite en Secure attributen (CWE-1275) 🔵

| | |
|---|---|
| **Ernst** | 🔵 Laag |
| **CWE** | CWE-1275 — Sensitive Cookie with Improper SameSite Attribute |
| **OWASP 2021** | A04 — Cryptographic Failures |
| **NEN-7510** | A.8.23 — Webfiltering |
| **Bron** | Handmatige review `web.xml` / Tomcat cookie-configuratie |

**Code-locatie (afwezigheid):**
De `web.xml` bevat geen `<cookie-config>` met `<secure>true</secure>` en er is geen SameSite-attribuut geconfigureerd via een Tomcat-responsfilter. Het `JSESSIONID`-cookie wordt verzonden als:

```
Set-Cookie: JSESSIONID=…; Path=/openmrs; HttpOnly
```

`Secure` en `SameSite=Strict` ontbreken beide. Zonder `Secure` stuurt de browser het sessiecookie ook over onversleuteld HTTP mee (relevant in combinatie met het ontbreken van HSTS — F-08). Zonder `SameSite` is het cookie kwetsbaar voor CSRF-aanvallen via cross-site requests.

**Pentest-bevestiging (F-09):** ZAP-scan bevestigde: `Cookie Without SameSite Attribute (Risk: Low, CWE-1275)`. Zie [PentestReport §14](../05-penetration-tests/PentestReport-OpenMRS.md#14-f-09--cookie-zonder-samesite-attribute-cwe-1275).

**Reële impact:** In combinatie met F-03 (session fixation) verhoogt dit het risico op sessie-onderschepping aanzienlijk. Op een ziekenhuisnetwerk zonder end-to-end TLS is het sessiecookie onderschepbaar, wat in combinatie met F-03 directe sessie-overname mogelijk maakt.

**Aanbeveling:**
```xml
<!-- web.xml -->
<session-config>
  <cookie-config>
    <http-only>true</http-only>
    <secure>true</secure>
  </cookie-config>
</session-config>
```
Configureer `SameSite=Strict` via een Tomcat `CookieSameSiteSupport`-filter of een reverse-proxy response-header.

**Status:** ✅ **Gemitigeerd** — `SameSiteCookieFilter` (applicatieniveau) + Tomcat `Rfc6265CookieProcessor sameSiteCookies="strict"` (JSESSIONID); Kali-hervalidatie 2026-06-17 bevestigt `SameSite=Strict`. ### 2.10.1 SQ8 — Reflected XSS in Swagger debug-endpoint (CWE-79) 🔴

- **Bron:** CodeQL `java/xss` (alert **#1**, severity **high**); onafhankelijk als **SQ8** in threat-modelling.
- **Bestand + regel:** `omod/.../web/controller/SwaggerDocController.java:27`
- **Code:**
  ```java
  return "<h1>Debugging Tag: " + tag + "</h1>";
  ```
  De `tag`-parameter wordt ongesanitized gereflecteerd in een HTML-response. Het endpoint valt **buiten** `AuthorizationFilter` (categorie C, trust boundary TB6) — de XSS is zonder authenticatie bereikbaar.
- **Pentest:** endpoint retourneert HTTP 404 (Swagger uitgeschakeld via `webservices.rest.enableSwaggerDocs`). Niet functioneel testbaar.
- **Besluit:** geen code-fix doorvoeren — de productie-blootstelling is weggenomen via configuratie-gating (hardening-checklist §1). De aanbevolen definitieve fix (`HtmlUtils.htmlEscape(tag)`) staat als toekomstige actie genoteerd.
- **Status:** 🔴 **Open — bewust niet gemitigeerd** (code-fix niet valideerbaar; productie afgedekt door configuratie).

---

### 2.10.2 CWE-302 — Auth-filter fall-through na verlopen sessie (CodeQL #908)

- **Bron:** CodeQL `java/user-controlled-bypass` (alert **#908**, severity **high**) + handmatige review.
- **Bestand + regels:** `AuthorizationFilter.java:86` (ontbrekende `return`) en `:113` (optionele Basic-Auth-tak).
- **Code (vóór fix):**
  ```java
  httpResponse.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Session timed out");
  // ← géén return → uitvoering liep door naar chain.doFilter()
  ```
  Na een verlopen sessie werd de 401 verstuurd, maar de request werd alsnog doorgegeven aan de filterketen.
- **Fix:** `return`-statement toegevoegd na `sendError()` (commit `e3f3c7d`). Alert #908 (optionele Basic-Auth-tak) geverifieerd niet exploiteerbaar en als geaccepteerd risico gedismissed — zie [06-mitigatie §3](../06-mitigatie-en-validatie/06.md#3-authorizationfilter--session-timeout-fall-through-cwe-302-opgelost--alert-908-geaccepteerd-risico).
- **Status:** ✅ **Volledig gesloten** — fall-through gefixed (commit `e3f3c7d`); alert #908 `state: fixed` na scan 2026-06-16 (F-03 sessie-rotatie sloot de control-flow). Zie [06-mitigatie §3b](../06-mitigatie-en-validatie/06.md#3b-codeql-javausers-controlled-bypass-908--geaccepteerd-risico-false-positive).

---

### 2.10.3 CWE-532 — Mogelijk gevoelige data in log (CodeQL #4)

- **Bron:** CodeQL `java/sensitive-log` (alert **#4**, severity **high**).
- **Bestand + regel:** `omod/.../helper/LayoutTemplateProvider.java:124`
- **Code:**
  ```java
  log.warn("Found invalid token while parsing GlobalProperty " + propertyName + " : " + token);
  ```
  De waarde `token` (inhoud van een global property) wordt via string-concatenatie gelogd.
- **Reële impact:** in déze context bevat de gelogde property *adres-layout-defaults* — geen credentials of PII. Het patroon (rauwe global-property-inhoud loggen) is wel onwenselijk; niet elke global property is per definitie niet-gevoelig.
- **Status:** 🟡 **Open — lage prioriteit.** Aanbevolen: log alleen de property-naam en het feit dát een token ongeldig is.

---

### 2.10.4 CWE-20 — Te ruime regex-range in log-parser (CodeQL #2,#3)

- **Bron:** CodeQL `java/overly-large-range` (alerts **#2** en **#3**, severity **medium**).
- **Bestand + regel:** `omod-common/.../helper/ServerLogActionWrapper.java:70`
- **Code:**
  ```
  (INFO|ERROR|WARN|DEBUG)\s.*?[-].*?\s((?:[A-z][A-z].+))\s[|](.*?)[|]\s((.*\n*)+)
  ```
  `[A-z]` omvat naast letters zes leestekens (ASCII 91–96). Het deelpatroon `((.*\n*)+)` heeft een geneste quantifier die gevoelig kan zijn voor catastrofaal backtracking (ReDoS).
- **Reële impact:** de parser verwerkt server-gegenereerde logregels, geen directe user-input; ReDoS-vector is beperkt. Primair een correctheids-/kwaliteitsbug.
- **Status:** 🟡 **Open — lage prioriteit.** Fix: `[A-Za-z]` i.p.v. `[A-z]`; geneste quantifier herzien.
